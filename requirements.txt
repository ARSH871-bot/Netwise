# Netwise Python dependencies
#
# Install with:  pip install -r requirements.txt

# --- Layer 1: Batfish orchestration ----------------------------------------
# Pinned deliberately. The pybatfish client and the Batfish service in the
# Docker container should be on matching versions -- skew between them causes
# confusing failures. This pin matches image batfish/allinone reporting
# Batfish 2025.07.07.2423. If you pull a newer image, bump this to match.
pybatfish==2025.7.7.2423

# Batfish answers come back as pandas DataFrames, and our analysis code works
# with them directly, so pandas is a direct dependency rather than an
# incidental one.
#
# A MAJOR pandas BUMP CANNOT BE MERGED ON A GREEN CI TICK.
#   pybatfish declares `pandas` with no version ceiling, so pip will install a
#   major version it has never been tested against. And the only code that
#   touches a real DataFrame -- every `.frame()` call in analysis/checks/ --
#   needs a live Batfish, which CI does not have. The tests that mention
#   DataFrames use fakes.
#
#   So on a major bump, CI green means "the tests that do not use pandas still
#   pass". Verify it the only way that works: an isolated venv with the pinned
#   pybatfish and the new pandas, running the pipeline against the real
#   container. That is how >=2.0 -> >=3.0.5 was checked (#131), and it gave
#   results identical to pandas 2.3.3.
#
#   Same shape as the pybatfish pin below: a dependency whose real behaviour
#   lives outside anything CI can reach.
pandas>=3.0.5

# --- Layer 2: AI explanation layer -----------------------------------------
# Official client for talking to a local Ollama server. Requires Ollama
# installed and running separately (not a pip package) -- see ai/Modelfile
# for the model this project builds and calls: netwise-warden.
ollama>=0.6.2

# --- Layer 3: Web interface ------------------------------------------------
# Chosen over Flask for the auto-generated API docs at /docs (useful evidence
# in a review) and native async, which the streaming chat pane will need.
fastapi>=0.141.1
uvicorn[standard]>=0.52.1

# FastAPI needs this to parse multipart form data -- i.e. file uploads. Without
# it, the config upload endpoint fails at import time rather than at request
# time, so it is a hard dependency, not an optional extra.
python-multipart>=0.0.32

# --- Testing ---------------------------------------------------------------
# Run the suite from the repository root:  pytest tests/ -v
# The current tests need neither Batfish nor Docker.
pytest>=9.1.1
