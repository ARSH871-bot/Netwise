# Document builds

The scripts that produce the Studio 5 submission documents, the class
presentation, and the two diagrams that go inside them.

Run any of them from anywhere — they resolve their own paths from `__file__`,
so there is nothing to configure:

```bash
python -P docs/document-builds/build_group_report.py
```

`-P` is deliberate. It keeps a stray module in the working directory from
shadowing a real one, and it is why `_guard.py` is imported with an explicit
`sys.path` line rather than a bare `import`.

| Script | Produces |
|---|---|
| `build_group_report.py` | `docs/Studio 5 - Group Final Report - Netwise.docx` |
| `build_client_letter.py` | `docs/Client Confirmation Letter - for Senaka to sign.docx` |
| `make_team_diagram.py` | `docs/Demo/team-architecture.png` |
| `build_pptx.py` | `docs/Demo/Netwise - Class Presentation.pptx` |
| `check_pptx.py` | nothing — measures the deck for text overflow and off-slide shapes |
| `add_appendix_b.py` | nothing — a one-off patch already applied to `build_group_report.py` |

## Two builders are deliberately absent

`build_reflection.py` and `build_sub_portfolio.py` are on disk in this folder
but **not tracked**, and `.gitignore` names them. They build one person's
reflection and evidence portfolio, and unlike the group report the identifiers
are not the problem — the reflective prose *is* the document, and it is a
written self-assessment of an individual. #290 excluded `/docs/Feedback/` for
that category and gave the reason: this repository was public until 31 August
and its visibility has changed twice, so a file that is only safe while a
setting stays where it is should not be tracked at all.

They still run the same way, and they are still out of the temporary directory
they were rescued from — which was the actual risk.

## Student names and IDs

`build_group_report.py` needs the cover-sheet line. It reads it from
`docs/identity.json`, which is **not tracked**. Copy `docs/identity.example.json`
to `docs/identity.json` and fill it in; the build fails loudly with that
instruction if the file is absent.

A member with no `student_id` renders as the name alone. That is deliberate:
two of the four IDs were genuinely unknown when this was written, and a cover
sheet listing two of four with IDs and saying nothing about it is worse than
one that visibly has a gap.

## Why the outputs are not in git

`.gitignore` ignores `*.docx`, `*.xlsx` and `*.pptx`, and its comment explains
the reasoning: a committed copy of a generated document is a second source of
truth that goes stale the first time anyone rebuilds. That argument only holds
while the *scripts* are in the repository — which, until 7 September, they
were not. They lived in a temporary directory, along with two diagrams
(`ownership-boundary.png`, `process-flow.png`) that were embedded in the Group
Final Report and existed nowhere else. A routine temp clean would have left a
submitted document unrebuildable.

That is the same asymmetry `#247` records at the bottom of `.gitignore`: a
missing output regenerates, a missing input does not.

The inputs these scripts read — the images in `docs/screenshots/` and
`docs/Demo/team-architecture.png` — are therefore committed alongside them.

## The rebuild guard

Every builder writes its document from scratch, so a rebuild discards anything
edited by hand in Word. That is not hypothetical:

- a GitHub Projects screenshot pasted straight into the Group Final Report was
  nearly dropped by a rebuild;
- the Client Confirmation Letter on disk was 62 words shorter than the script
  produces, because the instruction box had been deleted and a sentence
  rewritten before it was sent to the client.

So `_guard.py` compares the document on disk against what the script is about
to write, and **refuses** if they differ, printing what changed. It does not
merge and it does not choose. `--force` overrides it deliberately:

```bash
python -P docs/document-builds/build_client_letter.py --force
```

The comparison is load-bearing, not decorative: disabling it and re-running
the letter build reverts the sent version to the generated one.

| `docs/Demo/team-architecture.png` | generated by `make_team_diagram.py` |

The folder is named `screenshots/` for historical reasons; two of its five
files are drawn diagrams rather than captures, and the table above is how you
tell which is which.

**The two diagrams are not irreplaceable, and #311 first said they were.**
`tools/make_diagrams.py` (#289) generates both, and both SVGs are tracked in
`docs/images/`. What was missing is only the SVG-to-PNG step, because
python-docx cannot embed SVG — so the *content* was always recoverable and only
the rendering was not. Corrected here because the original claim was the more
alarming one and it was wrong.
